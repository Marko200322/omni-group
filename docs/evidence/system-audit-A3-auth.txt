Protected page prefixes: /dashboard, /admin, /dev
  - Missing session → redirect /login?next=<path>
  - /admin and /dev require isAdminRole(session.user.role)
  - Demo sessions blocked from /admin|/dev in production unless ALLOW_DEMO_AUTH=true
  - Admin layout ALSO rejects demo sessions always (defense in depth)

CSRF (mutating /api/* except GET/HEAD):
  - Exempt: login, login/2fa, register, forgot/reset, demo, contact, public billing quote(s)
  - Non-exempt: require csrf cookie==header OR same-origin Origin/Referer
  - Production: missing Origin+Referer fails unless CSRF header matches (good)
  - CSRF cookie: og_csrf, SameSite=Lax, httpOnly=false (double-submit style)
  - Session cookie: og_session, httpOnly=true, SameSite=Lax, secure via COOKIE_SECURE / HTTPS site URL / production default
  - SESSION_SECRET required in production (openSession returns null if missing)

Open redirects:
  - Login/register use safeInternalPath() — blocks //, ://, \, decoded equivalents
  - Post-login redirectTo from completeWebLogin is role-based /admin or /dashboard only
  - Client may use ?next= but only after safeInternalPath; non-admins hitting /admin still bounce via middleware/layout

Auth rate limits (middleware):
  - login, login/2fa, register, forgot-password, reset-password
  - contact form separately rate-limited

Demo auth:
  - /api/auth/demo disabled in production unless ALLOW_DEMO_AUTH=true
  - Demo sessions cannot call live Atina (fetchAtinaAuthenticated returns 403 demo_session)

Session contents:
  - Sealed HMAC cookie stores accessToken + refreshToken (BFF pattern)
  - Login JSON response returns user profile + redirectTo, NOT tokens
  - 2FA challenge path returns challengeToken only (5m JWT, separate secret from Bearer)

5) SECURITY FINDINGS (severity, blockers first)
================================================================================

BLOCKERS: none

[MEDIUM] CSRF double-submit token largely unused by browser clients
  Evidence: og_csrf is set in middleware, but app fetch() call sites (login, 2FA settings, etc.)
  do not send x-csrf-token. Protection effectively depends on Origin/Referer same-origin check
  + SameSite=Lax session cookie. Acceptable for modern browsers; weaker for non-browser or
  Origin-stripping clients that still present cookies.
  Recommendation: centralize fetch helper that always attaches CSRF header from og_csrf cookie
  for mutating BFF calls (do not weaken Origin check).

[MEDIUM] Platform admin role vocabulary mismatch (web vs Atina)
  Evidence: web isAdminRole includes superadmin/operator/owner; Atina requireAdmin is admin-only;
  users.role CHECK historically admin|user|moderator. Risk is confusion / uneven enforcement
  if roles are expanded without aligning both layers.
  Recommendation: single shared allowlist; keep platform role distinct from orgRole=owner.

[LOW] problem-hunter BFF status/signals lack requireAdminSession
  Evidence: apps/.../problem-hunter/status|signals only require authenticated non-demo session;
  Atina /status and /signals also authenticate-only (search/run is requireAdmin).
  listSignals is userId-scoped (not cross-tenant). status leaks tavilyConfigured boolean.
  Recommendation: if hunting is operator-only product surface, gate BFF + Atina with requireAdmin.

[LOW] csrfValid uses non-constant-time string equality
  Evidence: bff-csrf.ts cookie === header. Low practical risk for CSRF tokens.
  Recommendation: timing-safe compare if tightening CSRF.

[LOW / INFO] Session cookie embeds refresh token (sealed)
  Standard BFF pattern; theft of og_session is full account access until expiry.
  Mitigations present: httpOnly, secure defaults, HMAC seal, demo sandbox.

[INFO] CSRF exemptions for public auth + contact + quote are intentional
  Login/register/forgot/reset/demo/contact/quote must work without prior CSRF cookie.
  Mitigated by rate limits on auth + contact.
