## Zeleno na `main` u Actions vs branch protection (bez GitHub admin-a)

- **Inženjerski uslov:** posle `git push` na `main`/`master` ili merge PR-a, workflow **CI (monorepo)** (`.github/workflows/ci-monorepo.yml`) treba da završi svih **pet** job-ova: **`python`** (u branch protection listi obično **`Python (Doslednost dok + pytest)`** — [`GIT-BRANCH-PROTECTION.md`](./GIT-BRANCH-PROTECTION.md)), **`atina-saas`**, **`omnigroup-web`**, **`atina-system`**, **`compose`**. Job **`python`** pre `pytest` pokreće [`scripts/audit-doc-gate-references.ps1`](../scripts/audit-doc-gate-references.ps1) (doslednost u `*.md`, `*.txt`, `*.yml`, `*.yaml`, `*.ps1`, `*.ini`: `verify-monorepo` uz `omnigroup` / `SkipOmnigroup`, literal **`Python (Doslednost dok + pytest)`** gde se pominje `verify-monorepo`, plus `smoke:all` gde su navedeni `verify-monorepo` ili `smoke-stack`, plus par **`EVIDENCE-INDEX`** / **`NIVO-1-DRYRUN-LOG`** u istom fajlu gde se indeks pominje — **Doslednost dok** doc gate (md/txt + yaml/ps1/ini), uklj. taj par, u [`scripts/README.md`](../scripts/README.md)); isti audit je **prvi korak** i u lokalnom [`verify-monorepo.ps1`](../scripts/verify-monorepo.ps1) (job **`python`** / required check **`Python (Doslednost dok + pytest)`** — [`GIT-BRANCH-PROTECTION.md`](./GIT-BRANCH-PROTECTION.md)). Workflow koristi **`permissions: contents: read`** — za ove job-ove **nisu potrebni repo secrets**.
- **Šta i dalje može zahtevati neko sa pravima na org/repo:** da su **GitHub Actions** uključeni za repo i da politika orga ne blokira workflow fajlove. Ako run uopšte ne kreće, to rešava vlasnik repoa / org admin — ti i dalje možeš da dokažeš isti red **lokalno** gore.
- **Branch protection** (npr. obavezni status check pre merge-a) je **procesna** stavka u **CEO sekciji A** [`CHECKLIST-CEO-SISTEM.md`](../CHECKLIST-CEO-SISTEM.md) — **ne menja** komande koje moraju da prođu; zeleni gate je isti kao u skripti ili u Actions.
- Koraci za vlasnika repoa (GitHub Settings, PR obavezan, status check opciono): **[`GIT-BRANCH-PROTECTION.md`](./GIT-BRANCH-PROTECTION.md)**.
- U **required status checks**, job **`python`** se u listi često vidi kao **`CI (monorepo) / Python (Doslednost dok + pytest)`** (stariji run-ovi mogu još prikazati `Python (doc audit + pytest)` ili `Python (pytest)` — vidi napomenu u [`GIT-BRANCH-PROTECTION.md`](./GIT-BRANCH-PROTECTION.md)).

## Koraci — sa GitHub-om (Actions na `main`)

1. Instaliraj **Git** (i po želji **GitHub CLI** `gh`) na mašini sa pristupom repou.
2. `git fetch` / `git checkout main` / `git pull` — proveri da je lokalno usklađeno sa onim što ide na `main`.
3. `git push` (ili merge PR-a u `main` po procesu tima).
4. U repou: **Actions** → workflow **CI (monorepo)** → poslednji run na `main` → svi job-ovi **zeleni** (`python` / **`Python (Doslednost dok + pytest)`** — [`GIT-BRANCH-PROTECTION.md`](./GIT-BRANCH-PROTECTION.md): **Doslednost dok** doc gate (md/txt + yaml/ps1/ini), uklj. par **`EVIDENCE-INDEX`** / **`NIVO-1-DRYRUN-LOG`**, u [`scripts/README.md`](../scripts/README.md); zatim `pytest`, `atina-saas`, `omnigroup-web`, `atina-system`, `compose` — tri `docker compose config`).
5. Kopiraj **URL tog run-a** u [`NIVO-1-DRYRUN-LOG.md`](./NIVO-1-DRYRUN-LOG.md) (polje „Link na CI run:“ u bloku „Zapis (izvršen)“ ili novi blok).
6. U [`NIVO-1-MASTER-CHECKLIST.md`](../NIVO-1-MASTER-CHECKLIST.md) označi **F.4** sa `[x]`.

## Zašto agent okruženje često ne može F.4 (samo preko GitHub-a)

Na mašinama bez `git` / `gh` u PATH i bez pristupa GitHub nalogu, **ne možeš** da potvrdiš **F.4** kroz Actions — ali **isti inženjerski red** i dalje može lokalno: [`verify-monorepo.ps1`](../scripts/verify-monorepo.ps1) (job **`python`** / required check **`Python (Doslednost dok + pytest)`** — [`GIT-BRANCH-PROTECTION.md`](./GIT-BRANCH-PROTECTION.md)). Stavka **F.4** u master listi tada zatvara **vlasnik repoa** po internom pravilu (evidencija u [`NIVO-1-DRYRUN-LOG.md`](./NIVO-1-DRYRUN-LOG.md) po izboru).

## Windows — `git` „nije prepoznat“ u PowerShell-u

1. Instaliraj **Git for Windows**; posle instalacije **zatvori i ponovo otvori** terminal (PATH se osvežava).
2. Ako i dalje ne radi, probaj punu putanju (prilagodi verziju/instalaciju):
   - `& "C:\Program Files\Git\bin\git.exe" --version`
   - `& "C:\Program Files\Git\cmd\git.exe" --version`
3. U **Cursoru**: Settings → traži **terminal integrated env** ili koristi profil koji uključuje Git `bin` u PATH.
4. Alternativa: **GitHub Desktop** (clone / push) ili **WSL** (`wsl`, pa `git` unutra) — i dalje u Actions proveri **CI (monorepo)** na `main`.
